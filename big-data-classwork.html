SECTION 1.1: UNDERSTANDING DATA AT SCALE

Data is no longer just information saved on a local disk. It exists across a multi-tier scale continuum:

Gigabyte (GB) → Terabyte (TB) → Petabyte (PB) → Exabyte (EB)

  • 1 GB (109 bytes): Single high-resolution MRI scan.
  • 1 TB (1012 bytes): ~1,000 human genome raw sequence files (compressed).
  • 1 PB (1015 bytes): Entire sequence repository of the European Nucleotide Archive (ENA).
  • 1 EB (1018 bytes): Estimated global genomic data output generated by healthcare labs annually.

THE 5 Vs OF BIG DATA

Big Data is defined by five distinct operational dimensions:

  1. Volume: The sheer mass of data. Bio: INSDC sequencing archives. Non-Bio: YouTube 500 hours/min uploads.
  2. Velocity: Stream rate of data incoming. Bio: Oxford Nanopore real-time current streaming. Non-Bio: Stock market transactions.
  3. Variety: Structural diversity. Bio: FASTQ, BAM, VCF, and image files. Non-Bio: Smart city video, GPS, and tweet streams.
  4. Veracity: Data noise & uncertainty. Bio: Long-read base-calling error rates. Non-Bio: IoT sensor calibration drift.
  5. Value: Actionable insights extracted. Bio: Identifying a single actionable BRCA1 mutation. Non-Bio: Predictive traffic routing.
Important Note Big Data is defined by the operational threshold where data processing exceeds local memory and single-processor execution limits.
Did You Know? A single human genome is 3.2 billion base pairs (~3.2 GB raw text). But standard 30x coverage sequencing yields nearly 100 GB per patient!
Common Mistake Confusing Velocity with CPU clock speed. Velocity refers to the incoming rate of external data streams, not CPU processing cycles.
Bioinformatics Connection The NCBI Sequence Read Archive (SRA) holds over 50 Petabytes of public sequencing data—one of the world's fastest growing datasets.

SECTION 2.1: DATA STRUCTURE CATEGORIZATION

Data exists along a structural spectrum based on its schema rigidity:

  • Structured Data: Strict, pre-defined schema with rigid rows and columns. (e.g., SQL tables, CSV files).
  • Semi-Structured Data: Lacks rigid tabular schema, but contains tags or key-value markers to separate fields. (e.g., JSON, XML, FASTQ, VCF).
  • Unstructured Data: No predefined data model or internal organizational structure. (e.g., Cryo-EM images, raw audio, BAM files).

WORKED EXAMPLE 2.1: OPERATIONAL DB VS. BIG DATA PLATFORM

Dimension Operational RDBMS (MySQL) Big Data Platform (Hadoop / Spark)
Primary Goal Online Transactional Processing (OLTP) High-throughput Batch Analytics (OLAP)
Data Schema Schema-on-Write (Must define schema first) Schema-on-Read (Store raw, parse upon query)
Scaling Strategy Vertical Scaling (Bigger single server) Horizontal Scaling (Add commodity nodes)
Data Types Structured tabular data Structured, Semi-Structured, Unstructured
Important Note Over 80% of modern biological data is semi-structured or unstructured. Traditional SQL engines cannot scale to these dynamic formats.
Did You Know? The standard .fastq sequencing file is semi-structured: every read block consists of exactly 4 repeating metadata/sequence lines.
Common Mistake Assuming semi-structured data is unorganized. It is structured, but its schema is dynamic and self-describing per record.
Bioinformatics Connection Variant Call Format (.vcf) uses flexible key-value headers to report complex genomic mutations without sparse empty columns.

SECTION 3.1: SINGLE-NODE LIMITATIONS & HADOOP ARCHITECTURE

Single computers hit four physical computing bottlenecks at scale:

  • Memory Wall: Datasets larger than physical RAM force severe disk swapping.
  • Storage Wall: Individual hard drives cannot store petabytes of expanding genomic files.
  • Processing Wall: A single CPU core requires weeks to scan billions of sequence lines sequentially.
  • Failure Wall: Hardware fails. If a node crashes during a 48-hour run, all execution state is lost.

THE HADOOP CORE PHILOSOPHY

Hadoop uses clusters of commodity hardware nodes built on three core concepts:

  1. Distributed Storage (HDFS): Splitting large files into uniform blocks (128 MB) across nodes.
  2. Fault Tolerance via Replication: Automatically copying blocks across nodes (Replication Factor = 3).
  3. Data Locality: Shipping application code (~1 MB) to the node where data lives, avoiding huge network moves.
Important Note HDFS files are Write Once, Read Many (WORM). Files cannot be edited in-place; they can only be appended or replaced.
Did You Know? If a DataNode misses its 3-second heartbeat signal, NameNode marks it offline and orders re-replication of its missing blocks.
Common Mistake Assuming NameNode processes computational data. NameNode manages metadata only; if its RAM fills up, the cluster fails.
Bioinformatics Connection A 300 GB BAM file split into HDFS is automatically stored across 2,400 distinct 128 MB blocks for parallel alignment scanning.

Core Hadoop (HDFS + MapReduce) handles basic distributed storage and processing. But how do you handle low-latency database lookups, real-time log ingestion, or standard SQL queries over petabyte files without writing complex low-level Java code?

SECTION 4.1: ECOSYSTEM TAXONOMY AND ROLES

The Hadoop ecosystem consists of specialized tools built around HDFS storage and YARN scheduling:

  • HDFS: Distributed file system providing high-throughput storage access across commodity hardware.
  • MapReduce: Batch processing framework mapping data into key-value pairs for parallel reduction.
  • YARN: Cluster resource manager allocating CPU, RAM, and tasks across computing frameworks.
  • Hive: Data warehouse architecture translating SQL queries (HiveQL) into distributed execution jobs.
  • Pig: Procedural dataflow platform and language (Pig Latin) for transforming massive unparsed data streams.
  • HBase: Column-oriented NoSQL database providing real-time random read/write access to billions of rows.
  • Sqoop: Bulk transfer tool import/exporting structured data between relational databases and HDFS.
  • Flume: Distributed system for collecting and streaming high-volume operational event and log data into HDFS.
  • Apache Spark: In-memory compute engine executing data tasks up to 100x faster than traditional MapReduce.
Important Note YARN decouples resource management from computation, allowing Spark and MapReduce to run simultaneously over HDFS.
Did You Know? Hive was created by Facebook to enable analysts with SQL knowledge to query petabytes of data without writing raw Java MapReduce.
Common Mistake Confusing Hive with HBase. Hive is a batch data warehousing SQL system; HBase is a low-latency NoSQL database for instant record lookups.
Bioinformatics Connection Broad Institute's HAIL platform runs on Apache Spark to execute real-time genome-wide association queries over millions of samples.

Page 5 — The MapReduce Architecture

THINK

You have 10,000 text files of DNA reads and need to count how many times the word GENOME appears. You divide the files among 10 students (Mappers). Each student counts local occurrences. How do you sort and aggregate their separate results into a single global total without data bottlenecks?

SECTION 5.1: THE MAPREDUCE COMPUTATIONAL PIPELINE

MapReduce processes parallel data streams in five distinct steps:

  1. Input Splits: Divides raw file datasets into logical chunks parsed by RecordReader into raw <offset, line> pairs.
  2. Mapper Stage: Applies user map logic to emit key-value pairs <k1, v1> based on target extraction logic.
  3. Shuffle & Sort: Routes intermediate outputs across the network so every identical key lands on the same Reducer node.
  4. Reducer Stage: Receives grouped keys <k1, List(v1, v2...)> and aggregates total counts or statistics.
  5. OutputFormat: Writes final reduced outputs directly back to persistent HDFS storage blocks.
Important Note Shuffle & Sort is the most expensive phase because it generates intensive network I/O and disk write operations across nodes.
Did You Know? Intermediate Map output pairs are written to local disk on worker nodes—only final Reducer outputs are written back to HDFS.
Common Mistake Assuming Reducer instances communicate with one another. Reducers operate in total isolation without shared global state.
Bioinformatics Connection K-mer frequency spectrum calculation maps k-mer strings as keys, shuffling matching k-mers to single reducers for count analysis.

Page 6 — Worked Example 1: Genomic Word Count

THINK

How does MapReduce convert an unformatted line of sequence text into a clean key-value summary table? Let's trace a small execution dataset step-by-step through every phase of the pipeline.

SECTION 6.1: STEP-BY-STEP MAPREDUCE TRACE

Input Dataset Line: "Genome Genome Protein RNA Genome Protein"

STEP 1: INPUT SPLIT & RECORD READER

Input is converted into a raw Key-Value tuple: <0, "Genome Genome Protein RNA Genome Protein">

STEP 2: MAPPER STAGE

Mapper parses string tokens and emits key-value pairs <word, 1>:

<"Genome", 1>, <"Genome", 1>, <"Protein", 1>, <"RNA", 1>, <"Genome", 1>, <"Protein", 1>

STEP 3: SHUFFLE & SORT STAGE

Framework sorts keys alphabetically and groups values into single lists per key:

<"Genome",  [1, 1, 1]>
<"Protein", [1, 1]>
<"RNA",     [1]>

STEP 4: REDUCER STAGE

Reducer sums all numerical values in each key array:

Key "Genome"  : 1 + 1 + 1 = 3  ==> Emit <"Genome", 3>
Key "Protein" : 1 + 1     = 2  ==> Emit <"Protein", 2>
Key "RNA"     : 1         = 1  ==> Emit <"RNA", 1>

STEP 5: FINAL HDFS OUTPUT

Genome   3
Protein  2
RNA      1
Important Note Notice how Shuffle & Sort automatically transforms independent individual tuples into cleanly grouped list values.
Did You Know? Combiner functions act as local mini-reducers on Mapper nodes to aggregate intermediate output before network shuffle.

SECTION 7.1: GENOMIC VARIANT QUANTIFICATION

Input Dataset Line: "SNP Insertion Deletion SNP SNP Deletion"

================================================================================
STAGE 1: MAPPER PROCESSING
================================================================================
Input Tuple: <0, "SNP Insertion Deletion SNP SNP Deletion">

Mapper Intermediate Output:
  <"SNP", 1>
  <"Insertion", 1>
  <"Deletion", 1>
  <"SNP", 1>
  <"SNP", 1>
  <"Deletion", 1>

================================================================================
STAGE 2: SHUFFLE & SORT
================================================================================
Grouping & Sorting Engine:
  "Deletion"   ───> [1, 1]
  "Insertion"  ───> [1]
  "SNP"        ───> [1, 1, 1]

================================================================================
STAGE 3: REDUCER AGGREGATION & FINAL OUTPUT
================================================================================
Reducer Instance ("Deletion")  : Sum = 1 + 1 = 2     ──> <"Deletion", 2>
Reducer Instance ("Insertion") : Sum = 1     = 1     ──> <"Insertion", 1>
Reducer Instance ("SNP")       : Sum = 1 + 1 + 1 = 3 ──> <"SNP", 3>

Final HDFS File Output:
  Deletion    2
  Insertion   1
  SNP         3
Common Mistake Poor intermediate key choices lead to Data Skew—where one Reducer node gets 95% of data workload while other cluster nodes sit idle.
Bioinformatics Connection GATK and SAMtools use this exact key-grouping logic across distributed alignment files to compute per-base variant coverage.

Page 8 — Worked Example 3: Average Expression

THINK

In single-cell RNA sequencing, we track gene expression values across cells. To determine if Gene_A is overexpressed, we calculate its average value. Can a Reducer simply calculate an average by taking the mean of pre-averaged sub-totals? (Hint: Math Warning: Avg(20,25,30,35) ≠ Avg(Avg(20,25), Avg(30,35)) if counts differ!)

SECTION 8.1: NUMERICAL AGGREGATION PIPELINES

Input Dataset Records: "Gene_A 20", "Gene_A 25", "Gene_A 30", "Gene_A 35"

MATHEMATICAL ALGORITHM DESIGN

To calculate a mathematically valid average, the Mapper must emit a tuple containing both value and unit count: <Gene_ID, (Expression_Value, Count=1)>.

--------------------------------------------------------------------------------
STEP 1: MAPPER PROCESSING
--------------------------------------------------------------------------------
Input Records  : "Gene_A 20", "Gene_A 25", "Gene_A 30", "Gene_A 35"
Mapper Outputs : <"Gene_A", (20, 1)>
                 <"Gene_A", (25, 1)>
                 <"Gene_A", (30, 1)>
                 <"Gene_A", (35, 1)>

--------------------------------------------------------------------------------
STEP 2: SHUFFLE & SORT
--------------------------------------------------------------------------------
Grouped Tuple List:
  Key: "Gene_A" ===> [(20, 1), (25, 1), (30, 1), (35, 1)]

--------------------------------------------------------------------------------
STEP 3: REDUCER COMPUTATION
--------------------------------------------------------------------------------
total_sum   = 20 + 25 + 30 + 35 = 110
total_count = 1 + 1 + 1 + 1 = 4

average = total_sum / total_count = 110 / 4 = 27.5
Reducer Output: <"Gene_A", 27.5>
Important Note Calculating complex statistics (averages, variances) in MapReduce requires emitting custom object tuples holding state sums and counts.
Common Mistake Averaging pre-averaged numbers from different mappers leads to severe statistical bias when sample sizes per split differ.
